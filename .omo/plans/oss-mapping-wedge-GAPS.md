## Acceptance criteria for P0 closure

- **G-YAML-01 green:** A YAML example with a quoted-reserved-word column compiles and `validate` *executes* the generated SQL on an ephemeral DuckDB (and a BigQuery-dialect dry-run), catching `ORDER` alias and `Revenue ($)` quoting bugs — not just YAML syntax.
- **G-LEDGER-01 green:** Spec defines `is_unchanged(source)` hash, rule stable key, ledger table DDL with index, diff storage per-run volume at 40 files/week retention, replay concurrency protocol, and a benchmark showing `<2min` audit on 90-day history.
- **G-SCHEMA-01 green:** CI gate rejects a column-rename without a version bump; `validate` covers m:n + FK≡PK drift case; warehouse-variance matrix checked into repo.
- **G-MOAT-01 green:** Either (a) dirty-CRM benchmark shows Sato/TURL F1 > regex+statistical on abbreviation-heavy wide table with p99 <500ms, or (b) formally deferred to post-MVP research track with regex+statistical fallback as MVP.
- **G-HYBRID-01 green:** Serialization contract chosen; quality checks run as DuckDB SQL (no `to_pylist`) *or* `to_pylist` + serialization p99 measured at 30s window cadence; cold-start amortization model shows streaming p99 window latency < 50% of window interval.
